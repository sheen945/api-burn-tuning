# api-burn-tuning

> 给「烧 token」类工具（Token 燃烧器）摸清某个 AI 平台的限流口径，并算出又快又稳的最优调用参数。

## 简介

这是一个 WorkBuddy / Claude Code 技能（Skill）仓库，面向需要给大模型平台配置「Token 燃烧器」的场景：比如消耗赠送额度、冲积分活动、摸清新平台（智谱、硅基流动、火山方舟、阿里百炼、商汤日日新等）的限流模型。

给平台配燃烧器时最贵的错误，是没搞清它到底在限什么就去调参数——参数方向搞反，速度能差 400 倍（实测 4,000 token/分钟 vs 190 万 token/分钟）。本技能沉淀了一整套实测方法论和探测脚本：先用压力阶梯 + 并发爬坡搞清平台是按 rpm（每分钟请求次数）还是 tpm（每分钟 token 量）限流，再据此选择烧法和参数。

适合人群：需要给 LLM API 平台做用量冲刺/额度消耗的开发者、运营者，以及为自家 Agent 配「烧额度」子程序的人。

**触发词**：烧token、燃烧器、消耗额度、刷积分、限流、429、rpm、tpm、并发、填充字符数、API 用量。

## 功能特性

- **限流口径判别方法论**：不要靠猜。用压力阶梯把请求频率一点点压上去直到撞 429，看 429 报错原文（`rpm exhausted` / `tpm exhausted`）判断限流维度；原文没写则用「大单次低频率」与「小单次高频率」两组对比实验定位。
- **三种烧法横向对比**：填充式（塞长文本只要一字回答）、长输出式（让它疯狂输出）、雪球式（上下文滚动增大）。实测填充式碾压另外两种（33.7 万/分 vs 几千/分）——因为「读」比「写」快两个数量级。
- **单次填充大小寻优**：实测给出 3 万~40 万字符各档的单次耗时，定位「10 万字符 ≈ 2.8 秒」的甜点区间，避免单次过大导致耗时暴涨。
- **候选参数对比选型**：多组「填充大小 × 并发数」各跑 45 秒横向对比，选出「又快又稳」（零限流且不占满请求额度）的一组，降低被风控盯上的概率。
- **五个即改即用的探测脚本**：改开头 `KEY` / `BASE` / `MODEL` 三个常量即可换平台；结果边跑边写同名 JSON，中途挂了不丢数据；自带本地假 OpenAI 兼容接口，调程序本身时不花额度。
- **积分 ↔ token 换算实测法**：没有统一换算率（「写」比「读」贵约 2.7 倍），教你怎么用浏览器自动化精确读后台余额、按烧法各自实测换算率。
- **大量踩坑记录**：包括「用 token 估算判断烧完」导致的真实事故、网络抖动不能当致命错误、时段差异（深夜比中午快 2~7 倍）、撞 429 的自适应退避策略（实测省 30 分钟以上）等。

## 工作原理 / 技术栈

- **纯 Python 3 探测脚本**，只用标准库（`urllib.request` + `json`），零第三方依赖。
- 调用对象为 **OpenAI 兼容的 `/chat/completions` 接口**（改 `BASE` 即可指向任意兼容平台）。
- 方法论核心：**压力阶梯**（请求间隔从 8~10 秒压到零间隔连打）→ **并发爬坡**（1 → 2 → 3）→ **抓 429 原文**判口径 → 候选参数各跑 45 秒横向对比 → 选「又快又稳」组。
- 关键结论：rpm 限流时请求次数是稀缺资源，单次塞尽可能大；tpm 限流时贴着配额塞。平台往往有多层限制（rpm + 5 小时窗口积分 + 每周积分），窗口额度通常最早到顶。
- 收工判定铁律：**以平台后台真实剩余额度为准**（剩 5% 即停），token 换算比只用于进度展示，绝不能让程序据此停手。

## 安装与使用

把本仓库目录内容复制到你的技能目录下，文件夹名保持 `api-burn-tuning`：

- WorkBuddy / CodeBuddy：`~/.workbuddy/skills/api-burn-tuning/`
- Claude Code：`~/.claude/skills/api-burn-tuning/`

重启会话后即可通过触发词自动匹配。使用流程：

1. 运行 `scripts/_限流口径实测.py`，搞清输出是否占配额、输入上限、限流恢复时间、单次填充天花板。
2. 运行 `scripts/_烧法对比实测.py`，压力阶梯找 rpm 上限并对比三种烧法。
3. 运行 `scripts/_并发实测.py`，并发爬坡抓 429 原文。
4. 运行 `scripts/_推荐参数实测.py`，候选参数横向对比选出最终参数。

每个脚本约跑 5~10 分钟，**放后台跑**。结果写入同名 JSON 文件。

## 注意事项

- **脚本需要有效的平台 API Key**：通过环境变量（如 `SENSENOVA_API_KEY`）或改脚本顶部 `KEY` 常量提供。
- **换平台必须重跑**：不同平台 429 的报错文案、限流模型都不一样，结论不能套用。
- **风控风险**：把速度推到百万 token/分钟量级远高于正常使用，建议分段跑、留意账号是否异常，**别用付费额度刷**。
- **别用「连打两次就 429」这类小样本下结论**：必须阶梯式加压 + 记录每一档的请求次数/分钟。
- 查后台余额有几十秒延迟，检查间隔要留安全余量，或用比例阈值（剩 5%）天然兜底。
